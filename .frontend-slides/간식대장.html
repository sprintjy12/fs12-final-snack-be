기능은 도메인 단위, 나머지는 공통 레이어

프론트엔드

Next.js App Router

app/ 라우트 그룹으로 인증 ((auth)) 과 서비스 ((private)) 를 분리합니다.

features/ 는 도메인 UI, components/ 는 공통 UI 입니다.

화면 데이터는 TanStack Query, 폼·응답은 Zod. RouteGuard 와 GNB 는 권한별로 달라집니다.

app/
  (auth)/ 로그인 · 회원가입 · 초대 가입
  (private)/ admin · budget · purchase · profile
  products/ 목록 · 상세 · 내 상품
  cart/
api/ auth · product · cart · order · budget
hooks/ · schemas/ · types/ · lib/
백엔드

Express + Prisma

Routes → Controllers → Services → Repositories 단방향 레이어입니다.

DB 접근은 Repositories 에만 두고, 미들웨어 체인으로 인증·권한·검증을 탑니다.

Router → authenticate → authorize → Zod → Controller → Service → Repository → Prisma
routes/ URL · 메서드 · 누가 타는지
controllers/ req 값만 꺼내 응답으로
services/ 예산 · 상태 · 중복 규칙
repositories/ Prisma 조회 · 트랜잭션 · 락
middlewares/ · schemas/ · utils/

01

문제

승격 403 · 강등 15분

권한을 올려도 바로 막히고, 내려도 Access가 끝날 때까지 옛 권한이 남았습니다.

02

원인

JWT가 권한을 쥐고 있음

인가는 payload.role 기준. 이미 준 토큰은 서버가 바꿀 수 없습니다.

03

해결

JWT = 누구 · DB = 권한

매 요청 role / status를 DB에서 읽습니다. 재로그인 없이 다음 요청부터 반영됩니다.

authenticate
const payload = verifyAccessToken(accessToken);

const user = await findUserForAuthentication(
  payload.sub
);

req.user = {
  id: user.id,
  companyId: user.companyId,
  role: user.role,  // JWT가 아니라 DB
};

01

문제

F5 후 쿠키가 사라짐

Application > Cookies에 있던 refreshToken이 새로고침하면 빠졌습니다. 유실이거나 백엔드 Clear로 오인했습니다.

02

원인

DevTools의 시각적 착각

Path=/api/auth라 Application이 루트 경로 기준으로 안 보여준 것뿐입니다. refresh는 200으로 재발급됐습니다.

03

해결

Network가 진실

Request Cookies로 흐름을 확인합니다. Silent Refresh는 아직이라, 401 → refresh → 재시도는 다음에 붙입니다.

검증

Path=/api/auth
HttpOnly · Max-Age=604800

팀 자체 평가

마지막 프로젝트인 만큼 자신이 원하는 파트에 좀 더 집중할 수 있도록 각자 선택을 할 기회가 주어져서 좋았다.

AI를 단순히 내 작업을 시키는 도구가 아니라, 나와 함께 프로젝트를 완성해나가는 동반자로 사용할 수 있는 방법에 대해 고민할 수 있는 경험이 되고 있어서 만족스러웠다.

하나의 문제를 해결하기 위한 방법이 다양했기 때문에, ‘지금 내가 할 수 있는 선택지가 과연 최선이었을까, 더 나은 방식은 없었을까’ 싶은 고민이 매 순간 들었다. 그래서 기주님을 (정말로) 많이 귀찮게 해드렸다… (죄송합니다🤤💭)

매번 팀 순회 때마다 기주님께서 우리 프로젝트에 도움이 될만한 기술이나 모듈을 많이 소개해주셨는데, 어떤 것들은 실제 도입으로 이루어지기도 했고, 어떤 것들은 개인적인 경험이나 검토에 그치기도 했으나 그 과정에서 프로젝트를 바라보는 시야가 조금 더 트였다는 생각을 했다.
